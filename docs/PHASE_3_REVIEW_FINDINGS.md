## Revise now

1. **Reconnect/action lock inversion — corrected and tested.** Actions previously locked the Slack account before the owner, while reconnection locked the owner before the account. `SlackActions.account()` now takes the owner user and membership first and refreshes authoritative rows. A forced PostgreSQL overlap test passes. Per-request lock timeouts remain necessary; this test does not prove every future multi-account lock graph safe.
2. **Exhausted worker attempts lost receipt finalization — corrected and tested.** `claim()` previously failed a job at the attempt limit while a delivery could remain `sending`. `settle_exhausted_delivery()` retains uncertainty after durable intent and preserves a confirmed completion. Real Slack proposal/job regressions cover sending, queued and completed states.
3. **Cached authorization across provider reads — corrected and tested.** `authorized()` previously used identity-map cached membership/user rows after an intent commit. It now rereads those rows. A PostgreSQL test revokes a role during the GitHub marker read and proves the worker never reaches create. This is validation before sending, not a promise to cancel a request already accepted by a provider.
4. **Provider marker is insufficient exact-content evidence — Phase 4 reviewing.** GitHub marker matching must distinguish an existing exact payload from a manually edited or differently configured issue. A matching marker cannot safely turn changed content into an exact completion. The adapter/service owner is adding conflict semantics; shared worker integration waits for its verified contract.
5. **Capability and runtime drift — partially corrected.** Shared Compose and example configuration now include Slack credentials/app ID/signing/gate and LinkedIn publishing/version settings; no private configuration or runtime changed. Slack receipt flags now check current destination/source/expiry. The LinkedIn catalog still needs the separate draft/publishing capabilities wired after the provider phase verifies them.

## Research and test before claiming release behavior

- **Overall acknowledgement budget:** raw signatures, replay and warm acknowledgements pass, but a 750 ms lock timeout plus a 1.5-second network timeout plus other database/pool work is not an overall production bound. Establish a complete deadline, failure acknowledgement policy and measured warm/cold/pool-contention behavior on the chosen topology. [Slack timing](https://docs.slack.dev/interactivity/handling-user-interaction/), [Render Free](https://render.com/docs/free).
- **Remote update concurrency:** Jira's observed `updated` check before PUT and Slack's content read before `chat.update` are separate HTTP operations. Neither is an atomic remote compare-and-swap. Prefer narrow patches and provider-supported preconditions where verified; display conflict/overwrite limitations and investigate a test that simulates a remote edit between the read and write. [Jira edit issue](https://developer.atlassian.com/cloud/jira/platform/rest/v3/api-group-issues/#api-rest-api-3-issue-issueidorkey-put), [Slack update](https://docs.slack.dev/reference/methods/chat.update/).
- **Retention and erasure:** preserve minimum delivery/uncertainty tombstones while removing transcript text, embeddings, participant context and editable drafts according to an explicit policy. A request to delete personal data must not erase the only evidence needed to avoid an uncertain external resend. Recovery links and expired visitor data need bounded cleanup with disposable-data tests.
- **Model deployment:** preserve CPU-local inference for private local use; hosted Free demo must disclose deterministic synthetic/rules behavior. A configured model name is not an extraction-quality or hosted-capacity result. The approved implementation contract defines synthetic evaluation cases and metrics.

Responses must not enumerate accounts.

Finally, implement privacy export and an explicit erasure job/policy that cancels unsent work, retains unresolved write intent safely, removes content-bearing records in dependency order, and records a minimal non-content audit/tombstone. Do not perform a live purge as part of implementation or testing.
