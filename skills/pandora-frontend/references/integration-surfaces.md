# Honest integration surfaces

## Capability vocabulary

Distinguish implemented adapter, configured operator credentials, linked user grant, selected destination, required scopes/product access and permission for this command. A green connected badge cannot replace these boundaries.

Use tested server capabilities. Never make unavailable actions appear successful using fabricated demo responses in product code. Synthetic responses belong in identified tests.

## Source import

Keep the requested narrow flow: connect the authorized account, read the selected/latest artifact, preview real source, explicitly save, then normal indexing/review.

If promising the latest accessible meeting, active/inaccessible/absent/processing transcripts must be honest states rather than silent older fallback. Connecting cannot generate transcription. Explain format/provenance when API entries differ from edited documents.

Provider labels are not confirmed participant identity. Preserve resource IDs/chronology and complete bounded pagination. Reject oversized/incomplete imports when the contract requires completeness instead of returning successful partial data.

Match selected access to the save DTO/default. An omitted visibility field must not widen a restricted transcript. Reimport identity/hash should reopen unchanged authorized source without duplication; changed sources follow the defined conflict/revision path.

Coordinate request/proxy deadlines. Client cancellation does not necessarily undo an acknowledged save/write. Fence late responses and keep recoverable receipts.

## Review and handoff

Approval and delivery remain separate inside a merged visible stage. Show exact stored payload readably; full inspection can be secondary rather than raw JSON dominating the page.

Bind approval to current source/item versions, visibility, destination/credential generation, hash, expiry and authority. Required restricted/public disclosure is explicit. Do not drop selected items silently to fit a limit.

Distinguish rejection, content mismatch, partial result and uncertainty. Preserve a verified resource link when it exists with different content. Failed history GET is not proof nothing was sent. Refresh/reconciliation is read-only unless an explicit tested retry permits another write.

No automatic uncertain resend. Download-requested and queued-send are not delivery completion.

## Accounts and links, when in scope

Invitations should be email/role-bound and recipient-owned. Existing users authenticate as the matching account; an owner should not overwrite a global password to add membership.

Describe the actual recovery mechanism, including manual/operator assistance and absent email delivery. Remove private fragments into memory before submitting tokens in bodies. Account for initial rendering such as StrictMode and later hash changes. Do not persist tokens in query URLs, logs, captures or client storage.

Distinguish local erasure, retained collaborative data, operational tombstones and provider content. Preserve frozen/pending status access and explicit retry without premature erasure success.
